# DiaPredict

Вебсистема підтримки прийняття рішень для аналізу лабораторних показників у динаміці. Вона оцінює ймовірність появи запису про ЦД2 до очікуваного наступного візиту, прогнозує HbA1c на цю дату й показує індекс судинного ризику.

> Прогнозні показники є додатковою аналітичною інформацією; вони не встановлюють діагноз і не замінюють медичну оцінку.

## Можливості

Інтерфейс українською мовою, три вкладки:

1. **Скринінг** — для пацієнтів без попереднього записаного діагнозу ЦД2: оцінка ймовірності появи запису діагнозу ЦД2 до очікуваної дати наступного візиту.
2. **Ускладнення** — для пацієнтів із підтвердженим діабетом 2 типу: евристичний індекс факторів у балах, прогноз HbA1c, графіки та фактори способу життя.
3. **Лабораторні дані** — введення результатів аналізів із відображенням референтних норм.

## Моделі машинного навчання

| Файл | Призначення |
|------|-------------|
| `tier1_next_visit.joblib` | Tier 1: імовірність появи запису про ЦД2 до очікуваного наступного візиту |
| `tier2_next_visit.joblib` | Tier 2: прогноз HbA1c на очікувану дату наступного візиту |

Обидві моделі використовують один повний набір на останньому повному візиті: вік, глюкоза натще, HbA1c, ІМТ, систолічний тиск і тригліцериди. Записи з відсутнім будь-яким із цих значень не потрапляють до прогнозу; неповні пізніші дати не доповнюються старими вимірюваннями. Прогноз доступний для пацієнтів, у яких є щонайменше три повні візити: очікувану дату наступного візиту визначає медіана щонайменше двох попередніх інтервалів. Tier 1 оцінює ймовірність появи запису про ЦД2 до цієї дати; Tier 2 прогнозує HbA1c на цю дату, а цільові значення для навчання інтерполюються між фактичними вимірюваннями навколо неї. Усі ознаки відомі на момент останнього повного візиту.

Tier 1 прогнозує появу запису діагнозу ЦД2 у даних, а не дату біологічного початку захворювання. Прогноз HbA1c — оцінка майбутнього лабораторного значення за історичними записами. Дата наступного візиту є розрахунковою та базується на попередніх інтервалах пацієнта.

Оцінювання виконується на часовому тестовому відрізку, відокремленому за датою. Метрики й розмір тестової вибірки зберігаються у `results_v2/next_visit_metrics.json`. Перенавчити моделі можна командою `python train_next_visit_models.py`.

Звіт для читання людиною: `results_v2/evaluation_summary_uk.md`. Він містить кількість пацієнтів, які відповідають правилам відбору в застосунку, тестові метрики й 95% бутстреп-інтервали. Для застосунку використовується Tier 1 `tier1_next_visit.joblib`. Окремий експеримент на 365 днів із низькою якістю зберігається в `results_v2/experiments/` і не завантажується застосунком; його результати не об’єднуються з основною моделлю.

## Технології

- **Backend:** Python, FastAPI
- **Frontend:** HTML, JavaScript (без фреймворків)
- **ML:** scikit-learn / joblib

## Структура проєкту

```
.
├── app.py                         # FastAPI-сервер та API
├── index.html                     # Головна сторінка
├── js/
│   ├── api.js                     # Запити до API
│   ├── app_main.js                # Основна логіка інтерфейсу
│   ├── chart_utils.js             # Побудова графіків
│   └── lab.js                     # Лабораторні дані та референтні норми
├── tier1_next_visit.joblib        # Ймовірність появи запису про ЦД2 до наступного візиту
├── tier2_next_visit.joblib        # Прогноз HbA1c на наступний візит
├── train_next_visit_models.py     # Навчання та часове оцінювання моделей
└── README.md
```

## Запуск

1. Клонуйте репозиторій:

```bash
git clone https://github.com/ВАШ_НІК/НАЗВА_РЕПО.git
cd НАЗВА_РЕПО
```

2. (Рекомендовано) створіть віртуальне середовище:

```bash
python -m venv venv
venv\Scripts\activate        # Windows
source venv/bin/activate     # Linux / macOS
```

3. Встановіть залежності:

```bash
pip install fastapi uvicorn scikit-learn joblib pandas numpy
```

4. Запустіть сервер:

```bash
uvicorn app:app --reload
```

5. Відкрийте у браузері: <http://127.0.0.1:8000>
